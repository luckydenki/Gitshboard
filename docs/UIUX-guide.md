# UI/UX 점검 가이드

이 가이드는 UIUX 점검과 관련된 가이드입니다.
몇번째 점검이냐에 따라 처리할 점검의 범위가 달라집니다.


## 1차 점검

- 첫 점검은 구현이 끝난 화면을 실제 chrome 브라우저의 조작과 lighthouse를 통해 ux를 점검하세요

- 아래 후술할 "기본 점검"의 사항을 확인하여 작성하세요

- 점검 후에는 점검 결과에 다음을 남기세요
    - 재현 조건과 조작 순서
    - 관찰한 문제
    - 사용자에게 미치는 영향
    - 수정 제안을 남기세요. 
    
최소 수정 요청이 있어도 변경된 사용자 흐름에서 발견한 문제를 보고하세요. 반영 여부와 수정 범위는 메인 에이전트가 결정합니다.


## 1차 점검 이후의 모든 점검

- 처음 부터 점검하지 말고, 2차 점검부터는 이전에 발견한 문제와 수정된 코드의 영향 범위만 검증하세요.

- 메인 에이전트가 다음과 관련된 정보를 줄 것입니다. 해당 정보를 바탕으로 수정된 범위를 추론 하면 됩니다.
    - 이전에 발견된 문제
    - 수정된 파일
    - 수정 내용
    - 재현 및 확인 방법

이전 점검에서 정상으로 확인된 항목은 수정으로 영향을 받지 않았다면 다시 점검하지 마세요.
**중대한 문제가 없다면 추가 개선점을 찾기 위해 점검을 반복하지 마세요.**



## 기본 점검

1차 점검시 다음을 기본적으로 반드시 점검해야 합니다.

1. 컴포넌트 가능한 모든 데이터 로딩 상태에 대한 UI
2. (서버에서 가져온 데이터가 보여지는 경우) 데이터가 없는 상태에서의 UI
3. 모든 가능한 에러 상태의 UI 또는 에러 페이지의 이동
4. Lighthouse의 접근성 지표
5. 반응형 UI로 화면의 크기를 달리할 때 깨질 우려가 큰 UI
6. `CSS-guide`에서 세운 지침을 무시한 비일관적인 UI 디자인 (CSSguide는 `/docs/CSS-guide.md`참고)

각 점검 사항을 체크하세요.
