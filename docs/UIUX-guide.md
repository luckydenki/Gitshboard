# UI/UX 점검 가이드

`uiux_reviewer`는 구현이 끝난 화면을 실제 브라우저에서 열고, 변경된 사용자 흐름을 직접 조작해 UX를 점검합니다. 변경 범위에 해당하는 화면 상태, 좁은 화면에서의 배치와 조작, 키보드 탐색과 포커스 표시 등 사용자가 체감하는 부분을 확인하세요.

점검 결과에는 재현 조건과 조작 순서, 실제로 관찰한 문제, 사용자에게 미치는 영향, 수정 제안을 남기세요. 브라우저나 화면 상태에 접근할 수 없다면 점검하지 못한 범위와 이유를 메인 에이전트에 알리세요. 점검 에이전트의 작업은 브라우저 관찰과 피드백 작성까지입니다.

화면 잘림, 요소 겹침, 로딩 상태처럼 이미지로 보면 문제를 더 쉽게 파악할 수 있는 경우, `uiux_reviewer`는 브라우저의 스크린샷 기능으로 해당 화면을 캡처하세요. 캡처와 함께 화면 너비와 재현 조건을 메인 에이전트에 전달하세요. 최종 보고에 해당 항목을 남길 때 메인 에이전트는 전달받은 이미지 파일을 `report/screenshots/`에 저장하고 보고서에 상대 경로로 링크하세요. 이미지 파일을 전달할 수 없는 경우에는 재현 조건을 넘겨 메인 에이전트가 필요한 화면을 다시 캡처할 수 있게 하세요.

1. 메인 에이전트는 `component_worker`의 1차 구현이 끝나면 `uiux_reviewer`에 변경 범위와 확인할 화면을 전달합니다.
2. 메인 에이전트는 UX 피드백을 받아 요청 범위 안에서 조치할 항목을 기존 `component_worker`에 전달합니다. 조치할 항목이 없으면 점검을 끝냅니다.
3. 첫 수정이 끝나면 UX 에이전트에 지적한 항목의 재확인을 요청할 수 있습니다. 1차 점검을 포함해 **UX 점검과 피드백 전달은 작업당 최대 2회**입니다. 두 번째 피드백의 수정까지 반영했다면 루프를 종료하세요.
4. 점검을 마쳤을 때 미해결 문제나 수정 후 재확인하지 못한 항목이 있으면, 메인 에이전트는 프로젝트 루트의 `report/`에 작업별 Markdown 최종 보고를 남기세요. 파일명은 `YYYY-MM-DD-작업명-ux.md` 형식으로 작성하고, 각 항목의 상태, 재현 조건, 관찰한 문제, 다음에 확인할 내용을 적으세요. 채팅의 최종 답변에는 보고서 링크를 포함하세요.
