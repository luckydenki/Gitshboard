# 기본 UIUX 점검 가이드

어떤 컴포넌트의 기본 UI를 점검하는 가이드.

## 기본 사항

1. 점검 사항 10개 항목의 내용을 하나씩 체크하며 미구현된 부분을 확인한다.

2. 만약 어떤 컴포넌트가 점검 사항과 관련이 없다면 그건 통과로 취급한다. ex: 서버 데이터가 딱히 없는 컴포넌트라면 1, 2는 통과로 취급하면 됨

3. 9개중 7개 이상 통과시 통과로 처리한다.

4. [코드]는 코드에서 확인, [브라우저]는 브라우저에서 직접 확인해서 테스트하라는 의미. 브라우저 테스트는 기본을 Chrome으로 설정.

## 재점검 사항

재점검을 시행하는 경우, 이전 점검 사항에서 통과되지 못한 것만 점검한다.


## 점검 사항

1. [코드] 서버 데이터를 보여주는 컴포넌트에 로딩 UI가 존재하는 가

2. [코드] 에러 상태 및 재시도 관련 로직이 존재하는 가

3. [코드] 가져온 데이터가 없는 경우에 대한 UI가 존재하는 가

4. [브라우저] 데이터가 올바르게 보여지는 가

5. [브라우저] 뷰포트의 크기에 따라 UI가 화면을 넘어가거나 부모 범위를 벗어나거나 이유없이 사라지지 않고 안정적으로 보여지는 가 (반응형 UI 테스트)

6. [브라우저] 해당 컴포넌트가 있는 페이지의 Lighthouse 접근성 지표가 90점 이상을 유지하는 가

7. [코드] 해당 컴포넌트의 스토리 북을 작성 또는 수정하였는 가

8. [코드] `CSS-guide`에서 세운 기본적인 스타일 지침을 잘 지키고 있는 가

9. [브라우저] `Chrome` `Safari` `Firefox` 세 브라우저에서 일관성 있게 보여지는 가



## 채점표

- 채점 사항을 해당 컴포넌트 관련 스토리북 mdx 문서 맨 마지막 하단에 작성한다. (스토리 북 규칙과 별개로 동작함)
- 아래 예시대로 간단하게 작성하면 된다.

```mdx

5. 뷰포트의 크기에 따라 UI가 화면을 넘어가거나 부모 범위를 벗어나거나 이유없이 사라지지 않고 안정적으로 보여지는 가 (반응형 UI 테스트) (O)
```
