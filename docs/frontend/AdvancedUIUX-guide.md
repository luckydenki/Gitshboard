# Advanced UIUX GUIDE

특정 페이지 또는 컴포넌트의 UIUX를 심화적으로 점검하는 것에 대한 평가 가이드
(별도로 수행해달라고 하는 게 아니면 임의로 수행하지 말것, BasicUIUX 만이라도 잘 지키면 됨)

## 기본 사항

1. 점검 사항 4개 항목의 내용을 하나씩 체크하며 평가 한다.

2. 만약 어떤 컴포넌트가 점검 사항과 관련이 없다면 그건 통과로 취급한다. ex: 서버 데이터가 딱히 없는 컴포넌트라면 서버 데이터를 검증하라는 평가 항목은 통과로 취급하면 됨

3. 4개중 3개 이상 통과시 통과로 처리한다.

4. [코드]는 코드에서 확인, [브라우저]는 브라우저에서 직접 확인해서 테스트하라는 의미. 브라우저 테스트는 스토리북을 통해 간단히 확인.

5. 점검이 완료되면 보고서를 `/report/UX` 에 `(날짜)-(점검페이지 또는 컴포넌트).md` 로 작성한다.


## 재점검 사항

재점검을 시행하는 경우, 이전 점검 사항에서 통과되지 못한 것만 점검한다.


## 평가표

1.[브라우저] 특정 페이지 또는 컴포넌트의 렌더링 속도가 느린가 
- 느리다의 기준은 이탈률이 급격히 늘리기 시작하는 3초를 기준으로 함
- 서버 데이터를 보여주는 경우 네트워크의 TTFB를 같이 측정
- 20회 측정을 통해 대략적인 P95 P99를 확인할 것

2. [브라우저] Lighthouse 접근성 지표가 90점 이상인가
- 90점 이상이여도 Lighthouse가 지적한 요소를 작성할 것

3. [브라우저] AI SLOP UI/UX가 존재하는 가
- 어느 부분이 AI SLOP이 있는지 확인
- 디자인, UX 각각의 시점에서 확인
- 해당 UIUX를 가능하다면 캡처하여 찍어줄 것

4. [코드] 컴포넌트의 코드 길이, 역할과 책임 분리가 명확하게 되어있는가?
- 제대로 안되어있다면 어느 컴포넌트의 어떤 부분 분리 권장하는 지 작성
