# TDD FUNCTION SKILL

## 적용 범위

- 독립적인 함수, 유틸리티, 순수 비즈니스 로직의 구현 및 수정에 적용합니다.
- React 컴포넌트, JSX, 레이아웃, CSS 스타일 작업에는 적용하지 않습니다.
- 기존 함수의 수정 시에도 해당 함수의 테스트를 우선 확인합니다.

## 테스트 및 구현 파일 위치

- Backend 테스트: `backend/src/test/`
- Frontend 테스트: `frontend/test/`
- 실제 구현: 각 서비스의 `utils/` 디렉터리
- 테스트 프레임워크: Vitest
- 기존 프로젝트의 파일 구조와 import 규칙을 유지하세요.

## TDD 절차

### 1. RED

- 요구사항과 예상 입력 및 출력을 분석하세요.
- 아직 구현되지 않은 기능을 검증하는 단위 테스트를 작성하세요.
- 테스트를 실행하여 의도한 이유로 실패하는지 확인하세요.
- 테스트가 예상과 다른 이유로 실패했다면 테스트 설정 또는 테스트 코드를 수정하세요.

### 2. GREEN

- 실패한 테스트를 통과시키는 최소한의 실제 코드를 작성하세요.
- 테스트를 다시 실행하여 성공하는지 확인하세요.
- 이 단계에서는 불필요한 일반화와 추상화를 피하세요.

### 3. 테스트 확장

- 정상 입력, 경계 조건, 예외 상황 등 필요한 테스트를 추가하세요.
- 새 테스트에 대해서도 RED → GREEN 절차를 반복하세요.

### 4. REFACTOR

- 테스트가 모두 통과한 상태에서 중복 제거, 명명 개선, 일반화 등을 수행하세요.
- 리팩터링 이후 테스트를 다시 실행하여 기존 동작이 유지되는지 확인하세요.

### 5. 함수 문서화

구현이 완료되면 함수 바로 위에 `/** */` 형식의 JSDoc을 작성하세요.

반드시 다음 내용을 포함하세요.

- 함수명
- 개요: 함수의 목적과 동작
- 인자: 모든 인자 및 객체 내부 필드에 대한 설명
- 반환값: 반환 타입과 의미
- 사용 예시: 대표적인 사용 사례와 경계 사례
- 테스트: 관련 테스트 파일의 경로

## 완료 보고

- 구현한 함수와 테스트 파일의 경로를 보고하세요.
- RED 단계에서 확인한 실패 원인과 최종 테스트 결과를 보고하세요.
- 수행하지 못한 절차가 있다면 이유를 명시하세요.
