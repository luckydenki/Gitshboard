# GitHub API 설계 워크플로우

1. 대상 화면과 요청 범위를 확인한다. 작업 시작 시 최신 백엔드
   `AGENTS.md`, API 개설 가이드, API 타입 가이드를 읽는다.
2. `github_api_designer` 서브에이전트에 화면 경로, 사용자 요구사항, 기존 API,
   데이터 범위 및 제약을 전달한다. 결과는 구현 가능한 API 계약으로 받는다.
3. 메인 에이전트가 설계안에서 다음 항목을 검토한다.
   - 화면의 모든 값이 응답 필드 또는 명시된 계산식에 연결되는가?
   - GitHub 필드와 권한이 실제로 존재하고, 첫 화면과 전체 집계의
     조회 비용이 각각 설명되는가?
   - API를 나눴을 때 어느 화면이 먼저 표시될 수 있고,
     공유 원천 데이터의 중복 조회는 어떻게 처리되는가?
   - 빈 결과, 접근 권한 부족, 부분 수집을 응답에서 구별하는가?
4. 빠진 근거나 반례가 있으면 설계자에게 해당 항목만 돌려보낸다.
   지표의 의미나 제품 범위를 결정할 정보가 부족할 때는 선택지와
   화면에 생기는 차이를 정리해 사용자에게 묻는다.
5. 설계 요청이면 계약을 전달하고 종료한다. 구현도 요청받았다면
   검토한 계약을 구현자에게 넘기고, 프로젝트 지침에 따라 호출을 확인한다.
   프론트 연동과 UX 검토는 기존 프론트 워크플로우를 따른다.
