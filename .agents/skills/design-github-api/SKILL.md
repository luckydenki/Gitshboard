## 지침

Github API 설계 및 구현을 요구할 때 다음의 워크플로우로 설계한다.


## GitHub API 설계 워크플로우

1. 작업 시작 시 API 설계 대상이 되는 프론트엔드 화면을 확인하여 해당 화면에서 요구로 하는 모든 데이터를 체크한다. 사용자가 알려주지 않았다면 진행 전 꼭 물어볼 것

3. 메인 에이전트는 이를 바탕으로 그 데이터를 다음과 같이 나눠서 검토한다.
   a. Github API에서 곧바로 내려보내 줄 수 있는 데이터
   b. Github API에서 가져와 단순 통계적 연산(평균, 최대, 최소, 분산, 표준편차), 사칙연산으로 계산 가능한 데이터
   c. Rule based 로직, AI 학습, 대규모 데이터 수집 등이 필요로 하는 데이터

4. 3-a, 3-b에 해당하는 데이터에 대해서만 다음을 체크한다.
   - 필요로 하는 Github API (REST 방식과 GraphQL 방식)
   - REST 방식의 경우 필요한 최소 호출 횟수, GraphQL 방식의 경우 필요한 최소 점수
   - REST, GraphQL 각 방식에 따라 필요한 인자
   - 해당 API 호출을 위해 필요로 하는 최소 권한
   - 빈 결과, 접근 권한 부족, 부분 수집을 어떻게 응답에서 구별할 수 있는 지
   - 실제 백엔드에서 프론트로 나가는 API를 어떻게 나눌지


5. 이제 실제로 지금까지의 내용을 바탕으로 API를 설계한다.
   - 필요한 메서드 타입
   - 필요한 쿼리 파라미터와 각 쿼리 파라미터의 필요한 입력 검증
   - 발생 가능한 에러
   - 최종 응답 데이터
   - API 엔드포인트
