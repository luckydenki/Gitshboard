# SearchPagination

`SearchPagination`은 GitHub 사용자 검색 결과 목록을 이전 또는 다음 페이지 묶음으로 이동하는 페이지네이션 컴포넌트입니다.

사용자는 이전과 다음 버튼을 선택하여 동일한 검색어의 페이지를 이동할 수 있습니다.

---

## 주요 요구사항

### 1. 페이지 이동 버튼 표시

`SearchPagination`은 이전 페이지로 이동하는 `<` 버튼과 다음 페이지로 이동하는 `>` 버튼을 표시해야 합니다.

버튼 사이에는 현재 페이지를 나타내는 `children`을 렌더링합니다. 이 영역은 페이지 번호나 현재 위치를 사용자에게 알리는 용도로 사용할 수 있습니다.

### 2. `useSearchPagination` 페이지 버튼 자식 렌더링

검색 결과의 숫자 페이지 버튼은 `useSearchPagination`의 `PaginationButton` 결과를 `SearchPagination`의 `children`으로 전달하여 렌더링합니다.

훅에는 검색 결과 데이터, 현재 페이지, 페이지당 결과 수, 검색어와 `PageButton` 렌더러를 전달합니다. `PageButton`은 훅이 제공하는 `pageNumber`, `isActive`, `onClick`을 사용해야 합니다.

```tsx
const { PaginationButton } = useSearchPagination({
  data,
  page,
  per_page: { current: 10 },
  name,
  PageButton: ({ pageNumber, isActive, onClick }) => (
    <button
      aria-current={isActive ? "page" : undefined}
      onClick={onClick}
    >
      {pageNumber}
    </button>
  ),
});

return (
  <SearchPagination name={name} page={page} data={data}>
    {PaginationButton}
  </SearchPagination>
);
```

이렇게 전달된 숫자 페이지 버튼은 이전 및 다음 버튼 사이에 렌더링됩니다.

### 3. 검색어와 페이지 상태 유지

페이지 이동 시 검색어는 `name` 값으로 유지하고, 이동할 페이지는 URL 검색 매개변수에 포함해야 합니다.

예를 들어 `octocat` 검색의 1페이지에서 다음 버튼을 선택하면 다음 주소로 이동합니다.

```text
/search?name=octocat&page=11
```

### 4. 10페이지 단위 이동

이전 버튼은 현재 `page`에서 10을 빼고, 다음 버튼은 10을 더한 페이지로 이동합니다.

```text
현재 페이지: 11
이전 버튼: 1
다음 버튼: 21
```

### 5. 페이지 범위 제한

이전 버튼은 1보다 작은 페이지로 이동하지 않아야 합니다.

다음 버튼은 `data.total_count`보다 큰 페이지로 이동하지 않아야 합니다. 현재 구현에서는 `data.total_count`를 다음 이동의 최댓값으로 사용합니다.

### 6. Hover 상태

사용자가 버튼 위에 마우스 포인터를 올리면 선택 가능한 요소임을 알 수 있도록 배경색이 변경되어야 합니다.

```css
.pagination-button:hover {
  background-color: #9ca3af;
}
```

## 접근성 요구사항

### 버튼 사용

이전 및 다음 페이지 이동은 현재 화면의 검색 결과 상태를 변경하는 동작이므로 `<button>` 요소를 사용해야 합니다.

이를 통해 사용자는 다음과 같은 기본 기능을 사용할 수 있습니다.

* `Tab` 키를 사용한 버튼 포커스 이동
* `Enter` 또는 `Space` 키를 사용한 페이지 이동 실행
* 스크린 리더를 통한 버튼 인식

### 키보드 포커스

키보드 사용자가 현재 선택한 버튼을 확인할 수 있도록 명확한 포커스 스타일을 제공해야 합니다.

```css
.pagination-button:focus-visible {
  outline: 2px solid currentColor;
  outline-offset: 2px;
}
```

Hover 상태만 구현하고 포커스 상태를 생략해서는 안 됩니다.

## 테스트해야 할 동작

`SearchPagination` Story 또는 테스트에서는 다음 내용을 검증해야 합니다.

1. 이전 및 다음 버튼이 표시되는가
2. `useSearchPagination` 결과의 숫자 페이지 버튼이 `children`으로 렌더링되는가
3. 현재 페이지 버튼에 `aria-current="page"`가 적용되는가
4. 숫자 페이지 버튼을 선택하면 검색어를 유지한 URL로 이동하는가
5. 이전 버튼 실행 시 검색어를 유지한 채 10페이지 이전으로 이동하는가
6. 다음 버튼 실행 시 검색어를 유지한 채 10페이지 다음으로 이동하는가
7. 1페이지에서 이전 버튼을 실행해도 1보다 작은 페이지로 이동하지 않는가
8. 마지막 페이지에서 다음 버튼을 실행해도 `data.total_count`를 초과하지 않는가
9. `Tab`과 `Enter` 키로 버튼에 접근하고 실행할 수 있는가
10. Hover 스타일이 적용되는가

## 사용 예시

```tsx
<SearchPagination
  name="octocat"
  page="1"
  data={{ total_count: 100 }}
>
  <span>1</span>
</SearchPagination>
```

숫자 페이지 버튼을 포함하려면 훅의 결과를 자식으로 전달합니다.

```tsx
const { PaginationButton } = useSearchPagination({
  data,
  page,
  per_page: { current: 10 },
  name,
  PageButton,
});

<SearchPagination name={name} page={page} data={data}>
  {PaginationButton}
</SearchPagination>
```

11페이지에서 이전 페이지 묶음으로 이동하는 경우는 다음과 같습니다.

```tsx
<SearchPagination
  name="octocat"
  page="11"
  data={{ total_count: 100 }}
>
  <span>11</span>
</SearchPagination>
```

## 사용 시 주의사항

* `name`에는 현재 검색어를 전달하여 페이지 이동 후에도 검색 조건이 유지되도록 합니다.
* `page`는 숫자로 변환할 수 있는 문자열로 전달합니다.
* `data.total_count`가 없으면 다음 이동의 최댓값은 0으로 처리됩니다.
* 페이지 범위를 벗어나는 이동은 각각 1과 `data.total_count` 값으로 제한됩니다.
* 숫자 페이지 버튼은 `useSearchPagination`의 `PaginationButton` 결과를 `children`으로 전달해 표시합니다.
* `PageButton`은 `isActive`를 현재 페이지 표시로, `onClick`을 해당 페이지 이동으로 연결해야 합니다.
* 페이지 이동 버튼에는 Hover 효과와 키보드 포커스 효과를 함께 제공해야 합니다.
