# 프론트엔드 AGENTS.md


## 컴포넌트 및 UI 구현 및 수정

컴포넌트 및 UI 변경은 아래 기준에 따라 메인 에이전트가 직접 처리하거나 `component_worker`에 위임하세요. UX 점검과 피드백 작성은 `uiux_reviewer`가 담당하며, 점검과 피드백 전달은 `docs/UIUX-guide.md`를 따르세요.

직접 처리, 위임, UX 리뷰 여부는 코드 변경량보다 사용자가 체감하는 변경을 기준으로 판단하세요.

- **사용자 지시** : 대놓고 "간단하게" 와 같은 간단함을 나타내는 수식어를 썼거나 명시적으로 worker들을 호출하지 마라고 했을 경우 메인 에이전트가 직접 수정합니다.
- **단순 변경**. 기존 요소의 색상·테두리 색상·호버 효과, 오탈자나 기존 안내 문구, 기존 링크의 목적지만 국소적으로 바꾸는 경우 메인 에이전트가 직접 수정합니다. `component_worker`와 `uiux_reviewer` 호출은 생략합니다. 
- **그 외 컴포넌트 및 UI 변경**. `component_worker`에 위임합니다. 새 UI를 구현하거나 화면 배치나 요소 크기, 반응형 동작, 클릭 범위, 키보드 조작·포커스, 로딩·빈 목록·오류 상태가 달라지면 1차 구현 후 `uiux_reviewer`를 호출하세요. 카드 전체를 클릭 가능하게 하거나 목록 스켈레톤을 추가하는 경우가 여기에 해당합니다.


## Storybook 테스트

컴포넌트를 새로 만들게 되어 스토리북을 만들거나, 스토리북을 만들어달라는 직접적인 요청이 들어온다면 `storybook-worker`를 호출하여 위임하세요.

## API 연동 규칙

1. 실시간성이 매우 중요한 데이터, 또는 별다른 지시가 있는 게 아니라면 useQuery로 서버상태를 캐싱하여 재활용하세요. 지시가 없다면 기본 staleTime은 5분, retry는 3회입니다.
2. 도무지 useQuery 훅을 쓸 수가 없는 fetch라면 (예를 들면 순수 js 함수에서 호출해야 하는 등인 경우, useEffect에서만 호출해야 하는 코드인 경우 등) 그냥 쓰지 말고 일반 fetch 쓰세요.
3. 연동작업을 할 때 기존 컴포넌트 코드를 최소로 수정하세요
4. useQuery로 짠 코드는 반드시 커스텀 훅으로 분리하여 /hook/api 폴더 내에 작성하세요
